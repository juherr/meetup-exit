<objective>
Add the `--resume` capability to the `export` command. The orchestrator loads a per-export resume index from `<outDir>/.meetup-exit/index.json`, skips entity types already marked complete, and after fetching the remaining ones re-derives ALL CSV files from the complete JSONL by reusing `runConvert`. Index granularity is per entity-type (D-07) — minimal and sufficient.

Purpose: After a crash mid-export, the user can run the same command with `--resume` and recover without re-paying API cost for completed stages, while guaranteeing no duplicate rows in any CSV.
Output: New `src/export/resume-index.ts`, extended `ExportOptions` with `resume`, three completion write points in `runExport`, a CSV re-derivation step at end-of-resume, a CLI `--resume` flag, and a unit test for the resume-index helpers.
</objective>

Step C — load the resume index near the start of `runExport`:
Immediately AFTER the existing `if (!options.dryRun) { await Promise.all([ mkdir(... raw), mkdir(... csv), ... ]); }` block (so the output directories exist), add:
- `let resumeIndex: ResumeIndex = await loadResumeIndex(options.outDir, startedAt);`
- Per D-08, this works for both `--resume` runs (uses existing index) and fresh runs (returns empty fallback). When `options.resume === false`, the orchestrator must IGNORE the existing index — overwrite `resumeIndex` with `{ version: 1, exportedAt: startedAt, completedEntityTypes: [] }` in that branch so a fresh export does not accidentally skip stages. Implement this as:
  - `if (!options.resume) { resumeIndex = { version: 1, exportedAt: startedAt, completedEntityTypes: [] }; }`

Step D — gate each entity-type stage on the resume index:
Wrap the four entity-type sections in a `completedEntityTypes` check. Use the existing `options.includeXxx` flags AND the new resume gate:

- Groups: change the outer `if (options.includeGroups) { ... }` to `if (options.includeGroups && !resumeIndex.completedEntityTypes.includes("groups")) { ... }`.
- Events + event-details: change `if (options.includeEvents) { ... }` to `if (options.includeEvents && !resumeIndex.completedEntityTypes.includes("events")) { ... }`. Note: the event-details fetch loop lives inside this block, so a single gate covers both.
- RSVPs: change `if (options.includeRsvps && options.privacyMode !== "public-archive") { ... }` to `if (options.includeRsvps && options.privacyMode !== "public-archive" && !resumeIndex.completedEntityTypes.includes("rsvps")) { ... }`.
- Registration answers: change `if (options.includeRegistrationAnswers && options.privacyMode !== "public-archive") { ... }` to `if (options.includeRegistrationAnswers && options.privacyMode !== "public-archive" && !resumeIndex.completedEntityTypes.includes("registration-answers")) { ... }`.

Step E — persist the resume index after each stage completes successfully:
Immediately AFTER each of the four stage blocks (still inside the outer `try`), and only when `!options.dryRun`, add the mark-and-save sequence. The exact placement matters: do it AFTER all writes for that stage are issued but BEFORE moving on to the next stage. For events, this is after the event-details for-loop completes (i.e., after `eventDetailsMap` is fully populated). For RSVPs, after the rsvps for-loop. For registration-answers, after that for-loop. For groups, after the groups for-loop.

For each stage write:
```
if (!options.dryRun) {
  resumeIndex = markEntityTypeComplete(resumeIndex, "<stage>");
  await saveResumeIndex(options.outDir, resumeIndex);
}
```
The `<stage>` literal is one of `"groups"`, `"events"`, `"rsvps"`, `"registration-answers"`.

Important: if the stage was skipped (already in `completedEntityTypes`) the `markEntityTypeComplete` call is a no-op (idempotent), which is fine. But the persist-write also need not run when the stage is skipped — to avoid an unnecessary disk write, place the mark+save block INSIDE the gated `if` so it only runs when the stage actually ran.

Step F — re-derive ALL CSVs from the complete JSONL on resume runs:
After the entity-type loop AND inside the existing `if (!options.dryRun) { ... }` write block, BUT BEFORE the existing `writeXxxCsv(...)` calls that consume the in-memory row arrays, gate the in-memory CSV writes vs. the JSONL-derived CSV writes:

- If `options.resume === true`: skip the in-memory `writeGroupsCsv`/`writeEventsCsv`/`writePhotosCsv`/`writeRsvpsCsv`/`writeAttendeesCsv`/`writeRegistrationAnswersCsv` calls (the in-memory arrays only reflect entity types fetched in THIS run, not previously-completed ones). Instead, call `runConvert` with the export's own outDir as both input and output:
  - ```
    await runConvert({
      inputDir: options.outDir,
      outDir: options.outDir,
      includeMarkdown: options.includeMarkdown,
      privacyMode: options.privacyMode,
      ...(effectiveSalt !== undefined ? { pseudonymizationSalt: effectiveSalt } : {}),
      dryRun: false,
    }, logger);
    ```
  This re-reads the now-complete JSONL and re-derives every CSV (including `photos.csv` added in plan 02-01) and Markdown. Per D-06, this guarantees no duplicate rows.
- If `options.resume === false`: keep the existing per-CSV write block exactly as it is today (in-memory row arrays are authoritative for a fresh run).

Implement this branch with a single `if (options.resume) { ... } else { ... }` around the CSV-writing portion. Move the existing `writeGroupsCsv`/etc. calls into the `else` branch unchanged. The `writeChecksums(options.outDir)` call and the `Promise.all([writeManifest..., writeGdprReport...])` block remain shared (outside the if/else, in their current positions).

Note on Markdown: `runConvert` already handles markdown re-derivation when `includeMarkdown` is true (it re-writes `markdown/events/*.md` from `event-details.jsonl`). On resume, this is what we want — let `runConvert` regenerate markdown. The orchestrator's existing inline markdown writes during the event-details loop only happen for newly-fetched events; previously-completed events already have their markdown on disk and `runConvert` will overwrite with byte-equivalent output.

Step G — dry-run logging:
In the dry-run else branch, when `options.resume === true`, add a line: `logger.info("[dry-run] --resume: would load .meetup-exit/index.json; would skip already-completed entity types; would re-derive all CSVs via convert at end");`. Place it at the start of the dry-run else branch.

Do not change the `errorsWriter` or `errorRecords` logic introduced in plan 02-02 — those still run for any entity errors in this resume run. Do not change the `finally` block that closes writers.
