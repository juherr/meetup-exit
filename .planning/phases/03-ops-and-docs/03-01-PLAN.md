<threat_model>
Threats relevant to this plan (ASVS L1):

- **Secret leakage via check output**: doctor must NOT print the value of any MEETUP_* variable — only "set" or "missing". Printing env var values risks leaking tokens or key IDs in terminal output captured in logs or screenshots.
- **Private key content exposure**: The permissions check must stat the file (mode bits only) — it must NOT read the file content or log any key material.
- **Path traversal via env var**: MEETUP_PRIVATE_KEY_PATH is user-controlled. The check must use fs.stat on the resolved path to verify existence and permissions only — no file read, no shell expansion.
- **Denial of service via writable-check side effect**: The output-directory writability check must use fs.access (W_OK) rather than actually creating or writing a file, to avoid accidental state mutation.
</threat_model>

  <action>
    Create src/cli/commands/doctor.ts exporting a `doctorCommand` constant (Command instance, same pattern as verifyAuthCommand and probeNetworkCommand).

    The command has no required options. It reads MEETUP_AUTH_MODE from process.env (defaulting to 'access-token' if missing) and runs these checks in order:

    1. **Bun version check**: call `Bun.version` (available as global in Bun runtime). Print `✓ Bun version: {version}` if semver major >= 1, else `✗ Bun version: {version} (require ≥ 1.x)`.

    2. **Auth mode check**: print `✓ Auth mode: {mode}` if mode is one of 'access-token', 'jwt-bearer', 'refresh-token'. Print `✗ Auth mode: {mode} (unknown — expected access-token, jwt-bearer, or refresh-token)` otherwise. Mark as failed.

    3. **Required env vars check** (auth-mode aware — D-02):
       - `access-token` mode → check MEETUP_ACCESS_TOKEN
       - `jwt-bearer` mode → check MEETUP_CLIENT_KEY, MEETUP_AUTHORIZED_MEMBER_ID, MEETUP_SIGNING_KEY_ID, MEETUP_PRIVATE_KEY_PATH
       - `refresh-token` mode → check MEETUP_CLIENT_SECRET, MEETUP_REFRESH_TOKEN_FILE
       - unknown mode → skip (already failed in step 2)
       For each var: if present and non-empty → `✓ {VAR_NAME}: set`; if missing or empty → `✗ {VAR_NAME}: missing`. Do NOT print the value.

    4. **Private key permissions check** (jwt-bearer and refresh-token modes only — D-01):
       - Read MEETUP_PRIVATE_KEY_PATH from process.env.
       - Use `fs.stat` (from node:fs/promises) to get file stats. Do NOT read file content.
       - If stat fails (ENOENT or other) → `✗ Private key: {path} (file not found)`.
       - If stat succeeds: extract mode bits with `(stats.mode & 0o777)`. If mode === 0o600 → `✓ Private key: {path} (permissions: 600)`. Otherwise → `✗ Private key: {path} (permissions: {octal} — must be 600)`.

    5. **Output directory writability check**: use `fs.access('./exports', fs.constants.W_OK)` from node:fs/promises (constants from node:fs). Default path is `./exports`. If accessible → `✓ Output dir: ./exports (writable)`. If not (ENOENT or EACCES) → `✗ Output dir: ./exports (not writable — create directory or check permissions)`. Use W_OK constant, not file creation.

    After all checks, print a blank line, then either `All checks passed.` or `{N} check(s) failed.` where N is the count of failed checks.

    Exit code: process.exit(5) if any check failed, else natural exit (0). Do not call process.exit(0) explicitly.

    Use `unknown` for all caught errors. Cast to Error for .message. No `any`.
    All code comments in English.
    No interactive prompts.
