  <action>
    Create SECURITY.md at the repository root (not in src/ or specs/). GitHub links to this file automatically from the Security tab.

    Structure with these sections:

    **# Security**

    **## Pseudonymization salt is ephemeral** — Lead content (D-11). Explain that each `export --privacy-mode pseudonymized` run generates a new random salt in memory, which is NOT persisted to disk. As a result, member hashes (e.g., member_a3f19c2b) from one run are NOT the same as hashes for the same member in a different run. Do not cross-reference pseudonymized exports from different runs to correlate members — doing so breaks the pseudonymization contract. To compare archives over time, use a consistent export and run `convert` on the same raw JSONL.

    **## Private key** — The RSA private key file (MEETUP_PRIVATE_KEY_PATH) must be chmod 600 (owner read/write only). Never commit this file to version control. Store it in the `secrets/` directory which is gitignored. The doctor command (`meetup-exit doctor`) verifies the permissions automatically.

    **## Token handling** — Access tokens and refresh tokens are never logged or printed. If an error occurs involving auth, only the error type is shown — the token value is masked. Refresh tokens (refresh-token mode) are single-use: after each successful refresh, the new token is written back to MEETUP_REFRESH_TOKEN_FILE immediately. Do not share or log this file.

    **## Full-export sensitivity** — A full export (`--privacy-mode full`) contains complete member data: names, email addresses, all RSVP answers. Treat the `exports/` directory as sensitive. The `public-archive` and `no-email` modes exist to reduce PII in the output when sharing or publishing archives.

    **## Gitignore configuration** — The following paths must be in .gitignore to prevent committing secrets:
    - `.env` — contains credentials
    - `secrets/` — private key and other sensitive files
    - `exports/` — export archives may contain member PII

    These paths are already gitignored in this repository. Verify with `git check-ignore -v .env secrets/ exports/`.

    Keep the tone factual and actionable. No marketing language.
